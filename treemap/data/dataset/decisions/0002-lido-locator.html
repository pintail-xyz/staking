This contract is Lido's LidoLocator, the directory from which all of Lido's other contracts are read.

Grounds

  • On chainThe contracts it lists agree: the staking router and stETH both withdraw to the vault it names

Explanation

Lido's validators are identified from its own contracts, starting from a single address: the LidoLocator at 0xc1d0…2eb, which Lido's documentation lists among its deployed contracts. The locator is a directory; every other Lido contract used here (the staking router, the node operator registries, the withdrawal vault, stETH) is read from it on chain rather than taken from any list.

The addresses read from it are mutually consistent. The withdrawal credentials returned by the staking router and by stETH both point to the withdrawal vault the locator names, and stETH's Aragon kernel grants its permission manager role to Lido's Agent contract. A validator is counted as Lido's when its public key appears in one of Lido's node operator registries reached in this way; its operator is the node operator whose keys it is.

The decision would change if Lido's documentation named a different locator, or if Lido moved to a new one, which would be recorded as a new anchor.

What would change it

Lido documentation naming a different locator, or a move to a new one.

Evidence

Transactions and contract calls anyone can repeat on their own node.

  • LidoLocator.withdrawalVault(), StakingRouter.getWithdrawalCredentials(), Lido.getWithdrawalCredentials() agree
