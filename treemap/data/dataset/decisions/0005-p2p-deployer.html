Explanation

The account 0x588e…033a deploys P2P.org's contracts. Validators deposited through contracts it created are attributed to P2P.org as allocator and operator, while each client keeps its own withdrawal address. In October 2026 about 8,800 such validators were active, with some 0.37M ETH.

Identification. P2P.org's own code names the account: a mainnet test in its fee distributor repository gives it as P2P.org's deployer, and one in its SSV proxy repository uses it as contract owner. P2P.org's documentation lists mainnet contracts that this account created. On chain it created the four contracts that relayed about 23,000 deposits from 2023 onwards: two depositor contracts, an SSV proxy factory and the "Unlimited" depositor, whose deposits only P2P.org's operator can make.

Why P2P.org is the allocator. The client keeps the withdrawal address and can exit, but P2P.org holds the validator keys and decides how the stake behaves at the consensus layer, which is the control this dataset measures. P2P.org is therefore treated as an allocator with one operator, itself. The same rule is applied to every provider's depositor contracts. Of the 15,825 such validators that have exited, 462 were exited or consolidated by requests from the client's withdrawal address; the rest by voluntary exits signed with the validator key, which P2P.org (or its SSV operators) holds.

The deployer also created two Safe wallets, through the Safe factory, which sent 926 deposits. They are left out, since they are not depositor contracts. The decision would change with a P2P.org statement that the account deploys for others, or evidence that its key changed hands.

What would change it

A P2P.org statement that the account deploys for others, or evidence its key changed hands.

Evidence

Transactions and contract calls anyone can repeat on their own node.
