Explanation

The contract 0xdc8d…9ae0 is Blockdaemon's second batch deposit contract, BatchDeposit2, built for compounding (0x02) validators of up to 2,048 ETH. Validators first deposited through it are attributed to Blockdaemon as allocator and operator, while each client keeps its own withdrawal address. 324 validators were deposited through it between July 2025 and September 2026, from 14 sending accounts; 258 were active in October 2026 with about 130k ETH.

Identification. The README of Blockdaemon's batch deposit repository lists this address as BatchDeposit2's mainnet deployment. The contract's verified source is BatchDeposit2 from that repository, including the deadline check that Blockdaemon's staking API relies on when it reserves validators for a client. Five of the withdrawal addresses it deposited for also hold validators deposited through Blockdaemon's first batch contract (decision 0041).

Why Blockdaemon is the allocator. A client depositing through a provider's contract has chosen that provider, who generates the keys and runs the validators; the client keeps the withdrawal address. This is the rule applied to all providers' depositor contracts (decision 0005). Most of the validators' blocks carry client version strings only.

The decision would change with a Blockdaemon statement naming another contract, or evidence that keys Blockdaemon does not run are deposited through it.
