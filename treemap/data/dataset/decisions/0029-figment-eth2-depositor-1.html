Explanation

The contract 0xf2be…dab1 is a Figment depositor contract: validators first deposited through it are attributed to Figment as allocator and operator, while each client keeps its own withdrawal address. 73,344 validators were deposited through it between February 2022 and October 2026, from 551 sending accounts to 552 withdrawal addresses; about 17,400 were active in October 2026 with some 580k ETH.

Identification. Figment's documentation names two batch deposit contracts as its own. One of them was created by the account 0x1dae…3e3c, which also created this contract and a second one (decision 0030). All four have the same verified source code (FigmentEth2Depositor). A contract created by the account that created Figment's documented contract, with Figment's own code, is taken to be Figment's.

Why Figment is the allocator. A client depositing through a provider's contract has chosen that provider, who generates the keys and runs the validators; the client keeps the withdrawal address. This follows the general rule applied to providers' depositor contracts (as for P2P.org, decision 0005).

The largest client was Celsius (14,107 validators, all exited by January 2024; see decision 0028). Celsius held its customers' ETH, but under the same rule Figment, the provider it chose, is the allocator, with Celsius holding the withdrawal address.

Limits. The contract's deposit function is open to anyone while it is not paused, so a deposit through it does not by itself prove that Figment runs the validator; a client could in principle deposit keys run elsewhere. Explorer labels naming the contract as Figment's are recorded as leads. The decision would change with a Figment statement contradicting it, or evidence that some depositors use the contract with keys Figment does not run.

What would change it

A Figment statement contradicting it, or evidence some depositors use it with keys Figment does not run.
